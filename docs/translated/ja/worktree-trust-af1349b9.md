# Zed と信頼済みワークツリー

Zed におけるワークツリーとは、Zed が単体の「プロジェクト」として開くディレクトリまたは単一ファイルのことです。
`zed some/path` を実行したとき、ファイルやディレクトリを Zed にドラッグしたとき、またはユーザー設定ファイルを開いたとき、Zed はそのたびにワークツリーを開きます。

開かれたあらゆるワークツリーには、追加の設定オプションを含む `.zed/settings.json` ファイルが存在する場合があり、その内容によっては言語サーバーや MCP サーバーのインストールや起動が必要になることがあります。
ユーザーが自分自身のスレットモデルや許容できるリスクレベルに基づいて選択できるよう、すべてのワークツリーは最初は Restricted Mode で開始されます。
Restricted Mode では、`.zed/settings.json` に関連する項目のダウンロードおよび実行が禁止されます。
ワークツリーが信頼されるまでは、Zed は関連する信頼されていないアクションを実行せず、ユーザーの確認を待ちます。
これにより、ユーザーはプロジェクト設定や MCP サーバー、言語サーバーを確認する機会を得られます。

Zed は、グローバルにインストールするツールについては引き続き信頼します。
Prettier や Copilot などのグローバル MCP サーバーおよびグローバル言語サーバーは、ワークツリーの信頼状態とは無関係に、通常どおりインストールおよび起動されます。

ワークツリーが信頼されていない場合、Zed はタイトルバーの感嘆符アイコンによってその状態を示します。
このアイコンをクリックするか、`workspace::ToggleWorktreeSecurity` アクションを使用すると、ユーザーがそのワークツリーを信頼するかどうかを選択できるセキュリティモーダルが表示されます。

ワークツリーを信頼すると、その決定は Zed の再起動をまたいで保持されます。
`workspace::ClearTrustedWorktrees` コマンドを使用すると、信頼済みワークツリーをすべてクリアできます。
このコマンドは Zed を再起動し、信頼されていない設定や言語サーバー、MCP サーバーが残らないようにします。

この機能は、ローカルだけでなく SSH や WSL のリモートホスト上でも動作します。
これらの場合、Zed はホストごとに信頼情報を追跡します。

## 制限されるもの

Restricted Mode では、次のことが禁止されます。

- プロジェクト設定（`.zed/settings.json`）の解析と適用
- 言語サーバーのインストールおよび起動
- MCP サーバーのインストールおよび起動

## ワークツリーの包括的な信頼の設定

デフォルトでは、Zed は新しいワークツリーを信頼しません。
ユーザーは、新しいワークツリーごとに個別に信頼を付与する必要があります。
推奨はされませんが、次の設定によってすべてのワークツリーを信頼することもできます（[編集方法](./configuring-zed.md#settings-files)）:

```json [settings]
"session": {
  "trust_all_worktrees": true
}
```

自動的に信頼されたワークツリーは、再起動をまたいで保持されません。保持されるのは、手動で信頼したワークツリーのみです。
これにより、後で `trust_all_worktrees` を無効にした場合に、ユーザーが新たに信頼の判断を行うようにできます。

## 信頼の階層

これらは主に内部的な詳細であり、変更される可能性がありますが、一度に複数の信頼要求が承認される仕組みを説明する助けになります。
Zed には、要求内容に応じた複数の信頼レベルがあり、信頼度の低いものから高いものへ次のように並びます。

- "single file worktree"

空の Zed ウィンドウを開いた後に、単一ファイルを開くことができます。
ディレクトリを開いた後に、現在のディレクトリ外にあるファイルを開くこともできます。
よくある例としては `zed: open settings file` があり、この操作はそのファイル用の言語サーバーを起動し、新しい単一ファイルワークツリーを作成する場合があります。

言語サーバーがサプライチェーン攻撃を受けた場合にはリスクが生じるため、Zed はその起動をデフォルトで制限します。
そのファイルを含むディレクトリが信頼されているか、すべてのワークツリーが信頼されている場合を除き、単一ファイルワークツリーごとに個別の信頼付与が必要です。

- "directory worktree"

Zed でディレクトリを開いている場合、それは完全なワークツリーです。
プロジェクト設定で定義された複数の言語サーバーや MCP サーバーを起動することがあります。
そのため、下記の親ディレクトリの信頼付与が存在する場合を除き、ディレクトリワークツリーごとに個別の信頼付与が必要です。

ディレクトリワークツリーが信頼されると、言語サーバーおよび MCP サーバーのダウンロードと起動が許可されます。そのため、これが起きたときには対象ホストについて単一ファイルワークツリーの信頼も自動的に有効化します。これは、信頼されたディレクトリワークツリー内で言語サーバー機能を利用しつつ単一ファイルを開く場合に役立ちます。

- "parent directory worktree"

一度に複数のディレクトリワークツリーに対する信頼を決定できるよう、Zed で開いている親ディレクトリワークツリーについて、適切なチェックボックスをオンにすることで、そのすべてのサブディレクトリを信頼することができます。
これにより、その配下のすべてのサブディレクトリ、つまり現在のディレクトリワークツリーおよび将来作成されうるディレクトリワークツリーすべてに信頼が付与されます。
