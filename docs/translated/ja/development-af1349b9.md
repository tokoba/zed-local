# Zed の開発

Zed をソースからビルドするためのプラットフォーム別の手順については、次を参照してください。

- [macOS](./development/macos.md)
- [Linux](./development/linux.md)
- [Windows](./development/windows.md)

## キーチェーンへのアクセス

Zed はシステムのキーチェーンにシークレットを保存します。

しかし、macOS（およびおそらく他のプラットフォーム）で Zed の開発ビルドを実行しているときにキーチェーンへアクセスしようとすると、パスワードの入力を何度も求めるキーチェーンのプロンプトが大量に表示されます。

macOS では、これは開発ビルドに安定したアイデンティティがないことが原因です。たとえ「Always Allow」を選択しても、バイナリに何か変更があるたびに、OS は再びパスワードの入力を要求します。

これはすぐに煩わしくなり、開発のスピードを妨げます。

そのため、Zed の開発ビルドを実行するときは、デフォルトでシステムキーチェーンをバイパスする代替の認証情報プロバイダが使用されます。

> **注意:** これは開発ビルドの場合に**のみ**当てはまります。開発ビルドではない
> すべてのリリースチャネルでは、常にシステムキーチェーンが使用されます。

開発ビルドで実際のシステムキーチェーンを使って何かをテストする必要がある場合は、次の環境変数を設定して Zed を実行してください。

```
ZED_DEVELOPMENT_USE_KEYCHAIN=1
```

## パフォーマンス測定

Zed には、各フレームのレンダリングにかかる時間をプロファイルするためのフレーム時間測定システムが含まれています。これは、異なるバージョン間でレンダリングパフォーマンスを比較する場合や、フレームレンダリングコードを最適化する場合に特に有用です。

### ZED_MEASUREMENTS の使用

パフォーマンス測定を有効にするには、`ZED_MEASUREMENTS` 環境変数を設定します。

```sh
export ZED_MEASUREMENTS=1
```

有効にすると、Zed は各フレームのレンダリングにかかる時間を示すフレームレンダリングのタイミング情報を stderr に出力します。

### パフォーマンス比較のワークフロー

異なるバージョン間でフレームレンダリングのパフォーマンスを比較する際の一般的なワークフローは次のとおりです。

1. **測定を有効にする:**

   ```sh
   export ZED_MEASUREMENTS=1
   ```

2. **最初のバージョンをテストする:**

   - 計測したいコミットをチェックアウトする
   - Zed をリリースモードで起動し、5〜10 秒ほど使用する: `cargo run --release &> version-a`

3. **2 つ目のバージョンをテストする:**

   - 比較したい別のコミットをチェックアウトする
   - Zed をリリースモードで起動し、5〜10 秒ほど使用する: `cargo run --release &> version-b`

4. **比較結果を生成する:**

   ```sh
   script/histogram version-a version-b
   ```

`script/histogram` ツールは任意の数の測定ファイルを受け取り、指定したバージョン間のフレームレンダリングパフォーマンスデータを比較するヒストグラムの可視化を生成します。

### `util_macros::perf` の使用

ユニットテストをベンチマークするには、`util_macros` クレートの `#[perf]` 属性でそれらに注釈を付けます。次に、`cargo
perf-test -p $CRATE` を実行してベンチマークします。詳細な例と説明については、`crates/util_macros` および `tooling/perf` の rustdoc ドキュメントを参照してください。

## Windows での ETW プロファイリング

Zed は Event Tracing for Windows (ETW) によるパフォーマンスプロファイリングをサポートしており、CPU、GPU、メモリ、ディスク、ファイル I/O アクティビティを含む詳細なパフォーマンスデータを取得できます。データは `.etl` ファイルに保存され、標準的なプロファイリングツールで開いて解析できます。

ETW の記録には、アクセスされたファイルやレジストリキーのパス、プロセス名など、個人を特定できる情報やセキュリティ上センシティブな情報が含まれる場合があります。他者とトレースを共有する際には、この点に留意してください。

### トレースの記録

コマンドパレットを開き、次のいずれかを実行します。

- `zed: record etw trace`: CPU、GPU、メモリ、および I/O アクティビティを記録します
- `zed: record etw trace with heap tracing`: Zed プロセスのヒープ割り当てデータを含めます

Zed は `.etl` ファイルの保存場所を選択するよう促したあと、管理者権限を要求します。権限が付与されると、記録が開始されます。

### 保存またはキャンセル

トレースの記録中に、コマンドパレットを開いて次のいずれかを実行します。

- `zed: save etw trace`: 記録を停止し、トレースをディスクに保存します
- `zed: cancel etw trace`: 記録を停止しますが、保存は行いません

手動で停止しない場合、記録は 60 秒後に自動的に保存されます。
