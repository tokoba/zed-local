# Dev Containers

Dev Containers は、コンテナー構成内でプロジェクトの依存関係、ツール、設定を定義することで、一貫性があり再現性の高い開発環境を提供します。

リポジトリに `.devcontainer/devcontainer.json` ファイルが含まれている場合、Zed はプロジェクトを Dev コンテナー内で開くことができます。

## 要件

- Docker がインストールされ、`PATH` から利用できる必要があります。Zed は `docker` コマンドが存在することを要求します。Podman を使用している場合は、シンボリックリンクを使うなどして `docker` にエイリアスを張る必要があります: `sudo ln -s $(which podman) {some_known_path}/docker`。
- プロジェクトに `.devcontainer/devcontainer.json` ディレクトリ/ファイルが含まれている必要があります。

## Zed で Dev Containers を使用する

### 自動プロンプト

`.devcontainer/devcontainer.json` ディレクトリ/ファイルを含むプロジェクトを開くと、Zed はそのプロジェクトを Dev コンテナー内で開くかどうかを尋ねるプロンプトを表示します。"Open in Container" を選択すると、次の処理が行われます。

1. 必要に応じて Dev コンテナーイメージをビルドします。
2. コンテナーを起動します。
3. コンテナー環境に接続された状態でプロジェクトを再度開きます。

### 手動で開く

プロンプトを閉じてしまった場合や、後からプロジェクトをコンテナー内で開き直したい場合は、Zed のコマンドパレットから "Project: Open Remote" コマンドを実行し、プロジェクトを Dev コンテナーで開くオプションを選択できます。
または、{#kb projects::OpenRemote} バインディングから Remote Projects モーダルを開き、"Connect Dev Container" オプションを選択することもできます。

## Dev コンテナー構成を編集する

`.devcontainer/devcontainer.json` を変更しても、現時点では Zed はコンテナーを自動的に再ビルドまたは再読み込みしません。構成を変更した後は、次の手順を実行してください。

- 既存のコンテナーを手動で停止または強制終了します（例: `docker kill <container>`）。
- プロジェクトをコンテナー内で再度開きます。

## Dev コンテナーでの作業

接続されると、Zed はタスク、ターミナル、言語サーバーについてコンテナー環境内で動作します。
ファイルは Dev コンテナー仕様に従って、ワークスペースからコンテナー内へリンクされます。

## 既知の制限事項

> **注意:** この機能はまだ開発中です。

- **拡張機能:** Zed はまだコンテナー環境ごとに拡張機能を個別に管理しません。ホスト側の拡張機能がそのまま使用されます。
- **ポートフォワーディング:** `appPort` フィールドのみがサポートされています。`forwardPorts` やその他の高度なポートフォワーディング機能は実装されていません。
- **構成の変更:** `devcontainer.json` を更新しても自動的な再ビルドや再読み込みは行われず、コンテナーは手動で再起動する必要があります。
