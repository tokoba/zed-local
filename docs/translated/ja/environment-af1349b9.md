# 環境変数

***注意**: 以下は Zed 0.152.0 以降にのみ適用されます。*

Zed の複数の機能は環境変数の影響を受けます:

- [タスク](./tasks.md)
- [組み込みターミナル](./terminal.md)
- 言語サーバーの探索
- 言語サーバー

これらの機能を最大限活用するには、Zed がどこから環境変数を取得し、それらをどのように使用するかを理解しておくと役立ちます。

## Zed はどこから環境変数を取得するか？

Zed の起動方法によって、使用できる環境変数が変わります。これには、macOS Dock からの起動、Linux のウィンドウマネージャーからの起動、`zed` CLI からの起動などが含まれます。

### CLI から起動した場合

Zed が CLI（`zed`）経由で開かれた場合、その時点のシェルセッションの環境変数を継承します。

つまり、次のようにすると

```
export MY_ENV_VAR=hello
zed .
```

環境変数 `MY_ENV_VAR` は、Zed 内で利用可能になります。たとえば、組み込みターミナル内で利用できます。

Zed 0.152.0 以降では、Zed のインスタンスがすでに動作しているかどうかに関係なく、CLI の `zed` は自分の環境を *常に* Zed に引き渡します。Zed 0.152.0 より前のバージョンではこの挙動はなく、環境変数を継承するのは最初に起動した Zed インスタンスだけでした。

### ウィンドウマネージャー、Dock、ランチャーから起動した場合

Zed が macOS Dock、Linux 上の GNOME や KDE のアイコン、あるいは Alfred や Raycast のようなアプリケーションランチャーから起動された場合、それが継承できる周囲のシェル環境は存在しません。

それでも有用な環境を持てるようにするため、Zed はユーザーのホームディレクトリでログインシェルを起動し、その環境を読み込みます。この環境は Zed の *プロセス* に設定されるため、すべての Zed ウィンドウとプロジェクトがそれを継承します。

しかし、プロジェクトごとに異なる環境変数が必要なユーザー（たとえば `direnv`、`asdf`、`mise` を使用している場合）にとっては、これが問題になることがあります。そのため Zed は、プロジェクトを開くときに別のログインシェルを起動します。この 2 つ目のシェルはプロジェクトのディレクトリ内で実行されます。このシェルの環境はプロセスには *設定されません*。そうしておかないと、新しいプロジェクトを開くたびにすべての Zed ウィンドウの環境が変わってしまうためです。代わりに、この環境は保持され、タスクの実行、ターミナルのオープン、言語サーバーの起動時に渡されます。

## 環境変数はどこでどのように使用されるか？

環境変数には次の 2 つのセットがあります:

1. Zed プロセスの環境変数
2. プロジェクトごとに保存される環境変数

(1) の変数はプロセス自体に保存されており、起動されるあらゆるプロセス（タスク、ターミナル、言語サーバーなど）がデフォルトで継承するため、常に使用されます。

(2) の変数は機能に応じて明示的に使用されます。

### タスク

タスクは、複数の環境変数を合成した環境で起動されます。優先順位の低いものから高いものの順に並べると（後ろのものが前のものを上書きします）、次のとおりです。

- Zed プロセスの環境
- プロジェクトが CLI から開かれた場合: CLI の環境
- プロジェクトが CLI から開かれていない場合: プロジェクトのルートフォルダでログインシェルを実行して取得したプロジェクトの環境変数
- 必要に応じて、設定で明示的に構成された環境

### 組み込みターミナル

タスクと同様に、組み込みターミナルも合成された環境で起動されます。優先順位の低いものから高いものの順は次のとおりです。

- Zed プロセスの環境
- プロジェクトが CLI から開かれた場合: CLI の環境
- プロジェクトが CLI から開かれていない場合: プロジェクトのルートフォルダでログインシェルを実行して取得したプロジェクトの環境変数
- 必要に応じて、設定で明示的に構成された環境

### 言語サーバーの探索

いくつかの言語では、言語サーバーアダプターがユーザーの `$PATH` からバイナリを検索します。例:

- Go
- Zig
- Rust（[そのように構成されている](./languages/rust.md#binary) 場合）
- C
- TypeScript

この検索には、Zed は次の環境を使用します。

- プロジェクトが CLI から開かれた場合: CLI の環境
- プロジェクトが CLI から開かれていない場合: プロジェクトのルートフォルダでログインシェルを実行して取得したプロジェクトの環境変数

### 言語サーバー

言語サーバーを検索した後、Zed はそれらを起動します。

これらの言語サーバープロセスは、常に Zed のプロセス環境を継承します。ただし、言語サーバーの検索方法に応じて、追加の環境変数が設定されたり、プロセス環境が上書きされたりする場合があります。

- 言語サーバーがプロジェクト環境の `$PATH` から見つかった場合、そのプロジェクト環境が言語サーバープロセスに渡されます。プロジェクト環境がどこから来るかは、プロジェクトがどのように開かれたか（CLI 経由かどうか）に依存します。言語サーバーの探索については前のセクションを参照してください。
- 言語サーバーがプロジェクト環境内で見つからなかった場合、Zed はそれをグローバルにインストールして起動しようとします。この場合、プロセスは Zed のプロセス環境と、プロジェクトが CLI 経由で開かれている場合は CLI の環境を継承します。
