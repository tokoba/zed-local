# リリースノート

プルリクエストを作成すると、その本文はこの[プルリクエスト テンプレート](https://github.com/zed-industries/zed/blob/main/.github/pull_request_template.md)に基づいて自動的に入力されます。

```md
...

Release Notes:

- N/A _or_ Added/Fixed/Improved ...
```

毎週水曜日に、[`get-preview-channel-changes`](https://github.com/zed-industries/zed/blob/main/script/get-preview-channel-changes) を実行します。このスクリプトは、[Release](https://zed.dev/docs/development/release-notes) ドキュメントで説明されているとおり、プレビューにマージされたプルリクエストから `Release Notes` 行を収集します。

このスクリプトは、`Release Notes` 行より下にあるすべての内容を出力します。そこには、プルリクエストの作成者（Zed チームメンバーでない場合）やプルリクエストへのリンクといったメタデータも含まれます。
`N/A` を使用した場合、そのプルリクエストはスクリプトによって完全にスキップされます。

## `Release Notes` 行を作成する際のガイドライン

- ユーザーが Zed の変化を見たり感じたりできる場合にのみ、`Release Notes` 行を記述してください。
- `Release Notes` 行は、Zed のユーザーが変更内容を理解できるような書き方にしてください。
  ユーザーがエディタ開発者の専門用語を知っているとは想定せず、テキストエディタの利用者として理解できる言葉で変更内容を表現してください。
- プルリクエストの技術的な詳細を他のチームメンバー向けに記述したい場合は、それらは `Release Notes` 行より上に書いてください。
- ドキュメントへの変更は `N/A` と記載してください。
- プルリクエストで設定やキーバインドを追加・変更する場合は、その設定またはキーバインドを必ず明記してください。
  ユーザーに、この情報を探すためにドキュメントやプルリクエストを掘り下げさせないでください（もっとも、ドキュメントにも記載しておくべきです）。
- 変更を取り消すプルリクエストについては次のとおりです。
  - 取り消す対象が**すでにリリースされている**場合は、なぜリバートしたのかを説明する `Release Notes` 行を含めてください。これは破壊的変更となるためです。
- 取り消す対象が**まだリリースされていない**場合は、元の PR の `Release Notes` 行を `N/A` に編集してください。そうしないと、その項目が引き続き含まれてしまい、リリースノートのコンパイラがスキップすべきだと判断できない可能性があります。
