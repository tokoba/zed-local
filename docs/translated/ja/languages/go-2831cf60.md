# Go

Zed には Go のネイティブサポートがあります。

- Tree-sitter: [tree-sitter/tree-sitter-go](https://github.com/tree-sitter/tree-sitter-go)
- 言語サーバー: [golang/tools/tree/master/gopls](https://github.com/golang/tools/tree/master/gopls)
- デバッグアダプター: [delve](https://github.com/go-delve/delve)

## セットアップ

gopls は Go のパッケージマネージャー経由でインストールし、Homebrew や Linux ディストリビューションのパッケージマネージャー経由ではインストールしないことを推奨します。

1. パッケージマネージャー経由でインストールした gopls のバージョンがあれば、すべてアンインストールされていることを確認します:

```sh
# macOS Homebrew 用
brew remove gopls
# Ubuntu 用
sudo apt-get remove gopls
sudo snap remove gopls
# Arch 用
sudo pacman -R gopls
```

2. Go modules ツールを使って `gopls` を最新バージョンにインストール／更新します:

```sh
go install golang.org/x/tools/gopls@latest
```

3. `gopls` が PATH に含まれていることを確認します:

```sh
which gopls
gopls version
```

`gopls` が見つからない場合は、`.zshrc` や `.bash_profile` に `export PATH="$PATH:$HOME/go/bin"` を追加する必要があるかもしれません。

## インレイヒント

Zed はインレイヒント用に、次の初期化オプションを設定します:

```json
"hints": {
    "assignVariableTypes": true,
    "compositeLiteralFields": true,
    "compositeLiteralTypes": true,
    "constantValues": true,
    "functionTypeParameters": true,
    "parameterNames": true,
    "rangeVariableTypes": true
}
```

これは、Zed の設定でインレイヒントが有効になっている場合に、言語サーバーがインレイヒントを返すようにするためです。

次の設定を使用して

```json
"lsp": {
    "gopls": {
        "initialization_options": {
            "hints": {
                // ....
            }
        }
    }
}
```

これらの設定を上書きできます。

詳細については [gopls inlayHints ドキュメント](https://github.com/golang/tools/blob/master/gopls/doc/inlayHints.md) を参照してください。

## デバッグ

Zed は、Delve を使用した Go のテストおよびエントリポイント（`func main`）のゼロコンフィギュレーションデバッグをサポートしています。{#action debugger::Start}（{#kb debugger::Start}）を実行すると、これらのあらかじめ構成されたデバッグタスクのコンテキストに応じた一覧が表示されます。

より細かく制御したい場合は、`.zed/debug.json` にデバッグ構成を追加できます。以下に例を示します。

- [Delve の構成に関するドキュメント](https://github.com/go-delve/delve/blob/master/Documentation/api/dap/README.md#launch-and-attach-configurations)

### Go パッケージのデバッグ

特定のパッケージをデバッグするには、Delve の mode を「debug」に設定します。この場合「program」にはパッケージ名を指定します。

```json [debug]
[
  {
    "label": "Go (Delve)",
    "adapter": "Delve",
    "program": "$ZED_FILE",
    "request": "launch",
    "mode": "debug"
  },
  {
    "label": "Run server",
    "adapter": "Delve",
    "request": "launch",
    "mode": "debug",
    // Delve では program にパッケージ名を指定できます
    "program": "./cmd/server"
    // "args": [],
    // "buildFlags": [],
  }
]
```

### Go テストのデバッグ

パッケージのテストをデバッグするには、Delve の mode を「test」に設定します。
この場合も「program」はパッケージ名のままで、「buildFlags」を使ってタグを設定したり、「args」を使ってテストバイナリに渡す引数を設定したりできます（その方法の詳細は `go help testflags` を参照してください）。

```json [debug]
[
  {
    "label": "Run integration tests",
    "adapter": "Delve",
    "request": "launch",
    "mode": "test",
    "program": ".",
    "buildFlags": ["-tags", "integration"]
    // カーソル位置のテストだけに絞り込むには:
    // "args": ["-test.run", "$ZED_SYMBOL"]
  }
]
```

### ビルドとデバッグを分けて実行する

特定のコマンドでアプリケーションをビルドする必要がある場合は、Delve の `exec` モードを使用できます。この場合、`program` は実行ファイルを指し、`build` コマンドはその実行ファイルをビルドするようにします。

```json [debug]
[
  {
    "label": "Debug Prebuilt Unit Tests",
    "adapter": "Delve",
    "request": "launch",
    "mode": "exec",
    "program": "${ZED_WORKTREE_ROOT}/__debug_unit",
    "args": ["-test.v", "-test.run=${ZED_SYMBOL}"],
    "build": {
      "command": "go",
      "args": [
        "test",
        "-c",
        "-tags",
        "unit",
        "-gcflags\"all=-N -l\"",
        "-o",
        "__debug_unit",
        "./pkg/..."
      ]
    }
  }
]
```

### 既存の Delve インスタンスへのアタッチ

自分のマシン上で動作しているとは限らない既存の Delve インスタンスに接続する必要がある場合があります。そのような場合は、`tcp_arguments` を使って Zed から Delve への接続を設定できます。

```json [debug]
[
  {
    "adapter": "Delve",
    "label": "Connect to a running Delve instance",
    "program": "/Users/zed/Projects/language_repositories/golang/hello/hello",
    "cwd": "/Users/zed/Projects/language_repositories/golang/hello",
    "args": [],
    "env": {},
    "request": "launch",
    "mode": "exec",
    "stopOnEntry": false,
    "tcp_connection": { "host": "127.0.0.1", "port": 53412 }
  }
]
```

この場合、Zed は新しい Delve インスタンスを起動せず、既存のインスタンスを使用します。その結果、Zed 内には *ターミナルが表示されません*。デバッグ対象の stdin/stdout を扱うのは Delve インスタンス側なので、Delve インスタンスと直接やり取りする必要があります。
