# Java

Zed における Java の言語サポートは次のコンポーネントによって提供されます:

- Zed Java: [zed-extensions/java](https://github.com/zed-extensions/java)
- Tree-sitter: [tree-sitter/tree-sitter-java](https://github.com/tree-sitter/tree-sitter-java)
- Language Server: [eclipse-jdtls/eclipse.jdt.ls](https://github.com/eclipse-jdtls/eclipse.jdt.ls)

## OpenJDK のインストール

Java ランタイム (OpenJDK) をインストールする必要があります。

- macOS: `brew install openjdk`
- Ubuntu: `sudo add-apt-repository ppa:openjdk-23 && sudo apt-get install openjdk-23`
- Windows: `choco install openjdk`
- Arch Linux: `sudo pacman -S jre-openjdk-headless`

または [OpenJDK 23](https://jdk.java.net/23/) を手動でダウンロードしてインストールします。

## 拡張機能のインストール

{#action zed::Extensions}({#kb zed::Extensions}) を開き、`java` を検索してインストールできます。

## クイックスタートと設定

ほとんどのユーザーにとっては、Java サポートは追加設定なしでそのまま動作します。

- 一般的には、Zed プロジェクトのルートを Java プロジェクトのルートフォルダー（通常 `pom.xml` や `build.gradle` ファイルが存在する場所）にしてプロジェクトを開くことを推奨します。

- デフォルトでは、この拡張機能が最新の公式版 JDTLS を自動的にダウンロードして起動しますが、そのためには Java バージョン 21 が、`$JAVA_HOME` 環境変数として、または `$PATH` 上の `java(.exe)` 実行ファイルとしてシステムに存在している必要があります。プロジェクトの実行環境で、より低いバージョンの Java が必要な場合は、`java_home` 設定オプションを使って JDTLS の起動に使用する別の JDK を指定できます。

- JDTLS 用の **カスタム起動スクリプト** を用意することもできます。その場合は、`jdtls`（Windows では `jdtls.bat`）という名前の実行ファイルを `$PATH` 環境変数上に追加してください。これが存在する場合、拡張機能は JDTLS の管理されたインスタンスをダウンロード・起動せず、環境から提供されるものを使用します。

- [Lombok](https://projectlombok.org/) をサポートするには、JDTLS の起動時に lombok-jar をダウンロードし、Java-Agent として登録する必要があります。デフォルトでは、拡張機能がこれを自動的に処理しますが、これを望まない場合は、`lombok_support` 設定オプションを `false` に設定できます。

上記の設定を含めた、一般的な `settings.json` の例は次のとおりです。

```jsonc
{
  "lsp": {
    "jdtls": {
      "settings": {
        "java_home": "/path/to/your/JDK21+",
        "lombok_support": true,
      },
    },
  },
}
```

## デバッグ

デバッグサポートは、拡張機能が自動的にダウンロードして起動する、私たちの [Fork of Java Debug](https://github.com/zed-industries/java-debug) を通じて有効化されます。Zed でのデバッグの仕組みについての一般的な情報は、[Debugger Documentation](https://zed.dev/docs/debugger#getting-started) を参照してください。

Java での利用を開始するには、Debug メニューの `edit debug.json` ボタンをクリックし、ファイルの内容を次のように置き換えてください。

```jsonc
[
  {
    "adapter": "Java",
    "request": "launch",
    "label": "Launch Debugger",
    // プロジェクトに複数のエントリポイントがある場合は、使用するものを指定します:
    // "mainClass": "com.myorganization.myproject.MyMainClass",
    //
    // これは事実上、プログラムのエントリポイントにブレークポイントを設定します:
    "stopOnEntry": true,
    // デバッグプロセスの作業ディレクトリ
    "cwd": "$ZED_WORKTREE_ROOT",
  },
]
```

その後、Debug メニューから「Launch Debugger」シナリオを選択して、新しいデバッグセッションを開始できるようになります。

## Windows における起動スクリプト（Tasks とも呼ばれます）

この拡張機能は、テストやエントリポイントの横に表示される小さな再生ボタンを通じて、Zed 内からアプリケーションやテストを実行するためのタスクを提供します。ただし、Zed の拡張インターフェースの現時点での制限により、Windows と Unix 互換システムの両方で動作し、かつ Maven と Gradle の両方に対応するスクリプトを提供することはできません。そのため、標準では起動スクリプトは Mac と Linux でのみ動作します。

独自のタスクスクリプトを用意することで、Windows でも動作させるための比較的簡単な対処方法があります。その方法については [この Issue](https://github.com/zed-extensions/java/issues/94) を参照し、さらに詳しい情報については [Zed のドキュメントの Tasks セクション](https://zed.dev/docs/tasks) をお読みください。

## 高度な設定 / JDTLS の初期化オプション

JDTLS には、`initialize` LSP リクエストを通じて渡せる多くの設定オプションがあります。拡張機能は、設定内の `lsp.jdtls.settings.initialization_options` に記述された JSON オブジェクトを、そのまま JDTLS に渡します。利用可能なオプションや値については、[JDTLS Configuration Wiki Page](https://github.com/eclipse-jdtls/eclipse.jdt.ls/wiki/Running-the-JAVA-LS-server-from-the-command-line#initialize-request) を参照してください。以下は、上記の Wiki ページにあるサンプル設定を JDTLS に渡す `settings.json` の例です。

```jsonc
{
  "lsp": {
    "jdtls": {
      "settings": {
        // これは initializationOptions として JDTLS に送信されます:
        "initialization_options": {
          "bundles": [],
          // Zed プロジェクトのルートフォルダーが Java プロジェクトのルートと異なる場合に使用します:
          "workspaceFolders": ["file:///home/snjeza/Project"],
          "settings": {
            "java": {
              "home": "/usr/local/jdk-9.0.1",
              "errors": {
                "incompleteClasspath": {
                  "severity": "warning",
                },
              },
              "configuration": {
                "updateBuildConfiguration": "interactive",
                "maven": {
                  "userSettings": null,
                },
              },
              "import": {
                "gradle": {
                  "enabled": true,
                },
                "maven": {
                  "enabled": true,
                },
                "exclusions": [
                  "**/node_modules/**",
                  "**/.metadata/**",
                  "**/archetype-resources/**",
                  "**/META-INF/maven/**",
                  "/**/test/**",
                ],
              },
              "referencesCodeLens": {
                "enabled": false,
              },
              "signatureHelp": {
                "enabled": false,
              },
              "implementationCodeLens": "all",
              "format": {
                "enabled": true,
              },
              "saveActions": {
                "organizeImports": false,
              },
              "contentProvider": {
                "preferred": null,
              },
              "autobuild": {
                "enabled": false,
              },
              "completion": {
                "favoriteStaticMembers": [
                  "org.junit.Assert.*",
                  "org.junit.Assume.*",
                  "org.junit.jupiter.api.Assertions.*",
                  "org.junit.jupiter.api.Assumptions.*",
                  "org.junit.jupiter.api.DynamicContainer.*",
                  "org.junit.jupiter.api.DynamicTest.*",
                ],
                "importOrder": ["java", "javax", "com", "org"],
              },
            },
          },
        },
      },
    },
  },
}
```
