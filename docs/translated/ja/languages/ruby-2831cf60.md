# Ruby

Ruby のサポートは [Ruby extension](https://github.com/zed-extensions/ruby) を通じて利用できます。

- Tree-sitters:
  - [tree-sitter-ruby](https://github.com/tree-sitter/tree-sitter-ruby)
  - [tree-sitter-embedded-template](https://github.com/tree-sitter/tree-sitter-embedded-template)
- 言語サーバー:
  - [ruby-lsp](https://github.com/Shopify/ruby-lsp)
  - [solargraph](https://github.com/castwide/solargraph)
  - [rubocop](https://github.com/rubocop/rubocop)
  - [Herb](https://herb-tools.dev)
- デバッグアダプター: [`rdbg`](https://github.com/ruby/debug)

Ruby extension は ERB ファイルもサポートします。

## 言語サーバー

Ruby には複数の言語サーバーが利用可能です。Zed がサポートしているのは次の 2 つです。

- [solargraph](https://github.com/castwide/solargraph)
- [ruby-lsp](https://github.com/Shopify/ruby-lsp)

どちらも補完、診断、コードアクションなどの機能セットが重なっており、どれを使うかはあなた次第です。同時に両方を使用することはできない点に注意してください。

これら 2 つの言語サーバーに加えて、Zed は次のものもサポートしています。

- [rubocop](https://github.com/rubocop/rubocop) は Ruby 向けの静的コード解析およびリンターです。内部的には Zed によって言語サーバーとしても利用されていますが、その機能は solargraph や ruby-lsp を補完するものです。
- [sorbet](https://sorbet.org/) は、独自の段階的型システムを備えた Ruby 向け静的型チェッカーです。
- [steep](https://github.com/soutaro/steep) は、Ruby Signature (RBS) を利用する Ruby 向け静的型チェッカーです。
- [Herb](https://herb-tools.dev) は ERB ファイル向けの言語サーバーです。

言語サーバーを設定する際は、'dev: Open Language Server Logs' コマンドを使って LSP Logs ウィンドウを開くと便利です。そこで該当する言語インスタンスを選択すると、ログ情報を確認できます。

## 言語サーバーの設定

[Ruby extension](https://github.com/zed-extensions/ruby) は、`solargraph` と `ruby-lsp` の両方の言語サーバーをサポートします。

### 言語サーバーの有効化

サポートされているすべての Ruby 言語サーバー（`solargraph`、`ruby-lsp`、`rubocop`、`sorbet`、`steep`）について、Ruby extension は次の有効化シーケンスに従います。

1. 言語サーバーがプロジェクトの `Gemfile` に見つかった場合は、`bundle exec` 経由で利用されます。
2. `Gemfile` に見つからない場合、Ruby extension はシステムの `PATH` から実行ファイルを探します。
3. いずれの場所にも言語サーバーが見つからない場合、Ruby extension がそれをグローバル gem として自動的にインストールします（注: これは現在の Ruby gemset にはインストールされません）。

設定で `use_bundler` を `false` にすると、手順 1 をスキップしてシステムの実行ファイルを強制的に使用できます。

```json [settings]
{
  "lsp": {
    "<SERVER_NAME>": {
      "settings": {
        "use_bundler": false
      }
    }
  }
}
```

### `solargraph` の利用

`solargraph` は Ruby extension でデフォルトで有効になっています。

### `ruby-lsp` の利用

Settings ({#kb zed::OpenSettings}) の Languages > Ruby で言語サーバーを設定するか、設定ファイルに次を追加してください。

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": ["ruby-lsp", "!solargraph", "!rubocop", "..."]
    },
    // *.html.erb ファイルで herb と ruby-lsp を有効にする
    "HTML+ERB": {
      "language_servers": ["herb", "ruby-lsp", "..."]
    },
    // *.js.erb ファイルで ruby-lsp を有効にする
    "JS+ERB": {
      "language_servers": ["ruby-lsp", "..."]
    },
    // *.yaml.erb ファイルで ruby-lsp を有効にする
    "YAML+ERB": {
      "language_servers": ["ruby-lsp", "..."]
    }
  }
}
```

これにより `solargraph` と `rubocop` が無効になり、`ruby-lsp` が使用されます。

### `rubocop` の利用

Ruby extension は、違反検出と自動修正のための `rubocop` 言語サーバーもサポートします。

Settings ({#kb zed::OpenSettings}) の Languages > Ruby で言語サーバーを設定するか、設定ファイルに次を追加してください。

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": ["ruby-lsp", "rubocop", "!solargraph", "..."]
    }
  }
}
```

あるいは逆に、`ruby-lsp` を無効にして `solargraph` と `rubocop` を有効にすることもできます。

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": ["solargraph", "rubocop", "!ruby-lsp", "..."]
    }
  }
}
```

## `solargraph` のセットアップ

Solargraph は、フォーマットと診断がデフォルトでは無効になっています。次を `settings.json` に追加することで、Zed にそれらを有効にするよう指示できます。

```json [settings]
{
  "lsp": {
    "solargraph": {
      "initialization_options": {
        "diagnostics": true,
        "formatting": true
      }
    }
  }
}
```

### 設定

Solargraph は、プロジェクトルートにある `.solargraph.yml` というファイルから設定を読み込みます。このファイルの詳細については [Solargraph configuration documentation](https://solargraph.org/guides/configuration) を参照してください。

## `ruby-lsp` のセットアップ

Ruby LSP の設定は `initialization_options` に渡すことができます。例:

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": ["ruby-lsp", "!solargraph", "..."]
    }
  },
  "lsp": {
    "ruby-lsp": {
      "initialization_options": {
        "enabledFeatures": {
          // "someFeature": false
        }
      }
    }
  }
}
```

すべての設定オプションについては [Ruby LSP website](https://shopify.github.io/ruby-lsp/editors.html) を参照してください。

LSP の `settings` と `initialization_options` は、プロジェクト固有にすることもできます。例えば、特定のプロジェクトで [standardrb/standard](https://github.com/standardrb/standard) をフォーマッタおよびリンターとして使用する場合は、次を `.zed/settings.json` をあなたのプロジェクトリポジトリ内に追加します。

```json [settings]
{
  "lsp": {
    "ruby-lsp": {
      "initialization_options": {
        "formatter": "standard",
        "linters": ["standard"]
      }
    }
  }
}
```

## `rubocop` LSP のセットアップ

Rubocop では、安全でない自動修正はデフォルトで無効になっています。次を `settings.json` に追加することで、Zed にそれを有効にするよう指示できます。

```json [settings]
{
  "languages": {
    "Ruby": {
      // ruby-lsp をプライマリの言語サーバー、rubocop をセカンダリとして使用します。
      "language_servers": ["ruby-lsp", "rubocop", "!solargraph", "..."]
    }
  },
  "lsp": {
    "rubocop": {
      "initialization_options": {
        "safeAutocorrect": false
      }
    },
    "ruby-lsp": {
      "initialization_options": {
        "enabledFeatures": {
          "diagnostics": false
        }
      }
    }
  }
}
```

## Sorbet のセットアップ

[Sorbet](https://sorbet.org/) は、言語サーバーを含む Ruby 向けの一般的な静的型チェッカーです。

Sorbet を有効にするには、Ruby の `language_servers` のリストに `\"sorbet\"` を追加します。Sorbet をメインの LSP として利用する場合や、型チェックなど特定の機能のために別の LSP と併用する場合は、他の言語サーバーを無効にした方がよいかもしれません。

Settings ({#kb zed::OpenSettings}) の Languages > Ruby で言語サーバーを設定するか、設定ファイルに次を追加してください。

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": [
        "ruby-lsp",
        "sorbet",
        "!rubocop",
        "!solargraph",
        "..."
      ]
    }
  }
}
```

Sorbet のインストール、プロジェクトへのセットアップ、その挙動の設定に関するあらゆる事項については、[公式 Sorbet ドキュメント](https://sorbet.org/docs/overview) を参照してください。

## Steep の設定

[Steep](https://github.com/soutaro/steep) は、RBS ファイルを使用して型を定義する Ruby 向けの静的型チェッカーです。

Steep を有効にするには、Ruby の `language_servers` リストに `\"steep\"` を追加します。望むセットアップに応じて、順序を調整したり、他の LSP を無効にしたりする必要がある場合があります。

言語サーバーは Settings ({#kb zed::OpenSettings}) の Languages > Ruby で設定するか、設定ファイルに次の内容を追加してください:

```json [settings]
{
  "languages": {
    "Ruby": {
      "language_servers": [
        "ruby-lsp",
        "steep",
        "!solargraph",
        "!rubocop",
        "..."
      ]
    }
  }
}
```

## Herb の設定

`Herb` は `HTML+ERB` 言語でデフォルトで有効になっています。

## Tailwind CSS Language Server を Ruby で使用する

Ruby/ERB ファイルで [Tailwind CSS language server](https://github.com/tailwindlabs/tailwindcss-intellisense/tree/HEAD/packages/tailwindcss-language-server#readme) のすべての機能（自動補完、リントなど）を利用するには、`settings.json` に次の設定を追加して、CSS クラスをどこから取得すべきかを language server に教える必要があります:

```json [settings]
{
  "lsp": {
    "tailwindcss-language-server": {
      "settings": {
        "experimental": {
          "classRegex": ["\\bclass:\\s*['\"]([^'\"]*)['\"]"]
        }
      }
    }
  }
}
```

これらの設定により、ERB ファイル内の HTML 属性や、`class:` キーの後に続く Ruby/ERB の文字列に対して、Tailwind CSS クラスの補完が行われるようになります。例:

```rb
# Ruby ファイル:
def method
  div(class: "pl-2 <completion here>") do
    p(class: "mt-2 <completion here>") { "Hello World" }
  end
end

# ERB ファイル:
<%= link_to "Hello", "/hello", class: "pl-2 <completion here>" %>
<a href="/hello" class="pl-2 <completion here>">Hello</a>
```

## テストの実行

Ruby プロジェクトでテストを実行するには、ローカルの `.zed/tasks.json` 設定ファイルでカスタムタスクを設定できます。これらのタスクは、Minitest、RSpec、quickdraw、tldr などのさまざまなテストフレームワークで動作するように定義できます。以下に、エディタ内からテストを実行するためのタスク設定例を示します。

### Rails での Minitest

```json [tasks]
[
  {
    "label": "test $ZED_RELATIVE_FILE -n /$ZED_CUSTOM_RUBY_TEST_NAME/",
    "command": "bin/rails",
    "args": [
      "test",
      "$ZED_RELATIVE_FILE",
      "-n",
      "\"$ZED_CUSTOM_RUBY_TEST_NAME\""
    ],
    "cwd": "$ZED_WORKTREE_ROOT",
    "tags": ["ruby-test"]
  }
]
```

### Minitest

プレーンな minitest は行番号によるテスト実行をサポートせず、名前のみサポートしているため、代わりに `$ZED_CUSTOM_RUBY_TEST_NAME` を使用する必要があります:

```json [tasks]
[
  {
    "label": "-Itest $ZED_RELATIVE_FILE -n /$ZED_CUSTOM_RUBY_TEST_NAME/",
    "command": "bundle",
    "args": [
      "exec",
      "ruby",
      "-Itest",
      "$ZED_RELATIVE_FILE",
      "-n",
      "\"$ZED_CUSTOM_RUBY_TEST_NAME\""
    ],
    "cwd": "$ZED_WORKTREE_ROOT",
    "tags": ["ruby-test"]
  }
]
```

### RSpec

```json [tasks]
[
  {
    "label": "test $ZED_RELATIVE_FILE:$ZED_ROW",
    "command": "bundle",
    "args": ["exec", "rspec", "\"$ZED_RELATIVE_FILE:$ZED_ROW\""],
    "cwd": "$ZED_WORKTREE_ROOT",
    "tags": ["ruby-test"]
  }
]
```

同様のタスク構文は、`quickdraw` や `tldr` などの他のテストフレームワークにも使用できます。

## デバッグ

Ruby 拡張機能は、Ruby コードをデバッグするためのデバッグアダプターを提供します。Zed の UI および `debug.json` におけるこのアダプターの名前は `rdbg` で、内部的には [`debug`](https://github.com/ruby/debug) gem を使用しています。この拡張機能は、言語サーバーと同じ[起動ロジック](#language-server-activation)を使用します。

### 例

#### Ruby スクリプトのデバッグ

```json [debug]
[
  {
    "label": "Debug current file",
    "adapter": "rdbg",
    "request": "launch",
    "script": "$ZED_FILE",
    "cwd": "$ZED_WORKTREE_ROOT"
  }
]
```

#### Rails サーバーのデバッグ

```json [debug]
[
  {
    "label": "Debug Rails server",
    "adapter": "rdbg",
    "request": "launch",
    "command": "./bin/rails",
    "args": ["server"],
    "cwd": "$ZED_WORKTREE_ROOT",
    "env": {
      "RUBY_DEBUG_OPEN": "true"
    }
  }
]
```

## フォーマッタ

### `erb-formatter`

ERB テンプレートをフォーマットするには、`erb-formatter` フォーマッタを使用できます。このフォーマッタは、ERB テンプレートをフォーマットするために [`erb-formatter`](https://rubygems.org/gems/erb-formatter) gem を使用します。

フォーマットは、Settings ({#kb zed::OpenSettings}) の Languages > HTML+ERB で設定するか、設定ファイルに次の内容を追加してください:

```json [settings]
{
  "languages": {
    "HTML+ERB": {
      "formatter": {
        "external": {
          "command": "erb-formatter",
          "arguments": ["--stdin-filename", "{buffer_path}"]
        }
      }
    }
  }
}
```
