# Rust

Zed は Rust をネイティブにサポートしています。

- Tree-sitter: [tree-sitter/tree-sitter-rust](https://github.com/tree-sitter/tree-sitter-rust)
- Language Server: [rust-lang/rust-analyzer](https://github.com/rust-lang/rust-analyzer)
- Debug Adapter: [CodeLLDB](https://github.com/vadimcn/codelldb) (プライマリ), [GDB](https://sourceware.org/gdb/) (セカンダリ、Apple silicon では利用できません)

## インレイヒント

次の設定を使用すると、Rust における `rust-analyzer` のインレイヒント設定を変更できます。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "inlayHints": {
          "maxLength": null,
          "lifetimeElisionHints": {
            "enable": "skip_trivial",
            "useParameterNames": true
          },
          "closureReturnTypeHints": {
            "enable": "always"
          }
        }
      }
    }
  }
}
```

詳しくは Rust Analyzer マニュアルの [Inlay Hints](https://rust-analyzer.github.io/book/features.html#inlay-hints) を参照してください。

## ターゲットディレクトリ

`rust-analyzer` のターゲットディレクトリは `initialization_options` で設定できます。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "rust": {
          "analyzerTargetDir": true
        }
      }
    }
  }
}
```

`true` に設定すると、ターゲットディレクトリは `target/rust-analyzer` になります。`true` の代わりに `"target/analyzer"` のような文字列を指定することで、任意のディレクトリを設定できます。

## バイナリ

Zed が使用する `rust-analyzer` バイナリを設定できます。

デフォルトでは、Zed は `$PATH` 上から `rust-analyzer` を探して使用しようとします。そのバイナリで `rust-analyzer --help` が正常に実行できる場合は、それが使用されます。そうでない場合、Zed は自前の安定版 `rust-analyzer` をインストールして使用します。

代わりにプレリリース版の `rust-analyzer` をインストールしたい場合は、`settings.json` で `pre_release` を `true` に設定することで Zed に指示できます。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "fetch": {
        "pre_release": true
      }
    }
  }
}
```

Zed による `rust-analyzer` バイナリの検出を無効にしたい場合は、`settings.json` で `ignore_system_version` を `true` に設定します。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "binary": {
        "ignore_system_version": true
      }
    }
  }
}
```

任意の場所にあるバイナリを使用したい場合は、`path` と必要に応じて `arguments` を指定できます。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "binary": {
        "path": "/Users/example/bin/rust-analyzer",
        "arguments": []
      }
    }
  }
}
```

この `"path"` には絶対パスを指定する必要があります。

## 代替ターゲット

現在のプラットフォームとは異なるターゲット向け（例: macOS 上で実行しているときに Windows 向け）の診断を rust-analyzer に行わせたい場合は、次の Zed の LSP 設定を使用できます。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "cargo": {
          "target": "x86_64-pc-windows-msvc"
        }
      }
    }
  }
}
```

`rustup` を使用している場合は、次のコマンドを実行することで、利用可能なターゲットトリプル（`aarch64-apple-darwin`、`x86_64-unknown-linux-gnu` など）の一覧を確認できます。

```sh
rustup target list --installed
```

## LSP タスク

Zed は tree-sitter を使用したタスクを提供しますが、rust-analyzer には、LSP を介してファイル関連のタスクを問い合わせるための LSP 拡張メソッドがあります。
これはデフォルトで有効になっており、次のように設定できます。

```json [settings]
"lsp": {
  "rust-analyzer": {
    "enable_lsp_tasks": true,
  }
}
```

## Cargo の診断の手動取得

デフォルトでは、rust-analyzer では `checkOnSave: true` が有効になっており、バッファーを保存するたびに `cargo check --workspace --all-targets` コマンドが実行されます。
`checkOnSave: false` にして無効化した場合（上記のサーバー設定 JSON の例を参照）、Rust ファイル内で `editor: run/clear/cancel flycheck` コマンドを実行して cargo の診断を更新することで、手動で診断を取得することもできます。設定が有効な場合、プロジェクト診断エディタも `editor: run flycheck` コマンドで cargo の診断を更新します。

## サーバー設定の詳細

Rust-analyzer [manual](https://rust-analyzer.github.io/book/) では、rust-analyzer 言語サーバーのさまざまな機能や設定オプションについて説明しています。
Zed の Rust-analyzer はデフォルトのパラメーターで動作します。

### 大規模プロジェクトとパフォーマンス

大規模なプロジェクトでリソース使用量が非常に大きくなり得る主な注意点の一つは、次の機能を組み合わせて使用している場合です。

```
rust-analyzer.checkOnSave (default: true)
    Run the check command for diagnostics on save.
```

```
rust-analyzer.check.workspace (default: true)
    Whether --workspace should be passed to cargo check. If false, -p <package> will be passed instead.
```

```
rust-analyzer.cargo.allTargets (default: true)
    Pass --all-targets to cargo invocation
```

つまり、Zed が保存を行うたびに `cargo check --workspace --all-targets` コマンドが実行され、プロジェクト全体（ワークスペース）、lib、doc、test、bin、bench、および[その他のターゲット](https://doc.rust-lang.org/cargo/reference/cargo-targets.html)がチェックされることになります。

小規模なプロジェクトでは問題なく動作しますが、大規模になるとスケーラビリティに難があります。

代替案としては、[tasks](../tasks.md) を使用する方法があります。Zed にはすでに `cargo check --workspace --all-targets` タスクと、ターミナル出力上のエラーを cmd/ctrl クリックで移動する機能が用意されているため、保存時のチェック機能を制限するか、完全に無効にすることもできます。

保存時のチェック機能は cargo check の出力に基づく一部の診断を返す役割を担っているため、これをオフにすると、rust-analyzer は自身の[診断](https://rust-analyzer.github.io/book/diagnostics.html)に限定されることになります。

より詳細な設定が必要な場合は、マニュアルに記載されている `rust-analyzer.cargo.` や `rust-analyzer.check.`、`rust-analyzer.diagnostics.` などの設定も検討してください。
以下は Zed の settings.json のスニペットです（`lsp.rust-analyzer` セクションを編集して保存すると、言語サーバーは自動的に再起動します）。

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        // rust-analyzer から、cargo を使わない追加の診断を取得する
        // ことで、誤検知が含まれる場合がある（名前を指定して無効化可能）
        "diagnostics": {
          "experimental": {
            "enable": true
          }
        },
        // チェックを完全に無効化するには
        // （以下の cargo および check 設定はすべて無視される）
        "checkOnSave": false,
        // `lib` ターゲットのみをチェックする。
        "cargo": {
          "allTargets": false
        },
        // cargo check で `--workspace` の代わりに `-p` を使用する
        "check": {
          "workspace": false
        }
      }
    }
  }
}
```

### 複数プロジェクトのワークスペース

Cargo workspace の `[members]` に含まれていないが同じフォルダ内にある複数の Rust プロジェクトを rust-analyzer に解析させたい場合は、
ローカルプロジェクト設定の `linkedProjects` にそれらを列挙できます:

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "linkedProjects": ["./path/to/a/Cargo.toml", "./path/to/b/Cargo.toml"]
      }
    }
  }
}
```

### スニペット

rust-analyzer から、スニペットの内容に応じてコードを変換するカスタム補完項目を取得する方法があります:

```json [settings]
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "completion": {
          "snippets": {
            "custom": {
              "Arc::new": {
                "postfix": "arc",
                "body": ["Arc::new(${receiver})"],
                "requires": "std::sync::Arc",
                "scope": "expr"
              },
              "Some": {
                "postfix": "some",
                "body": ["Some(${receiver})"],
                "scope": "expr"
              },
              "Ok": {
                "postfix": "ok",
                "body": ["Ok(${receiver})"],
                "scope": "expr"
              },
              "Rc::new": {
                "postfix": "rc",
                "body": ["Rc::new(${receiver})"],
                "requires": "std::rc::Rc",
                "scope": "expr"
              },
              "Box::pin": {
                "postfix": "boxpin",
                "body": ["Box::pin(${receiver})"],
                "requires": "std::boxed::Box",
                "scope": "expr"
              },
              "vec!": {
                "postfix": "vec",
                "body": ["vec![${receiver}]"],
                "description": "vec![]",
                "scope": "expr"
              }
            }
          }
        }
      }
    }
  }
}
```

## デバッグ

Zed は `CodeLLDB` と `GDB` を用いて、Rust バイナリおよびテストのデバッグをインストール直後からサポートしています。これらの事前設定されたデバッグタスクのいずれかを起動するには、{#action debugger::Start}（{#kb debugger::Start}）を実行します。

より細かく制御したい場合は、`.zed/debug.json` にデバッグ構成を追加できます。以下の例を参照してください。

- [CodeLLDB の構成ドキュメント](https://github.com/vadimcn/codelldb/blob/master/MANUAL.md#starting-a-new-debug-session)
- [GDB の構成ドキュメント](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Debugger-Adapter-Protocol.html)

### バイナリをビルドしてからデバッグする

```json [debug]
[
  {
    "label": "Build & Debug native binary",
    "build": {
      "command": "cargo",
      "args": ["build"]
    },
    "program": "$ZED_WORKTREE_ROOT/target/debug/binary",
    // Rust を使用する場合、CodeLLDB（GDB ではない）では sourceLanguages が必須です
    "sourceLanguages": ["rust"],
    "request": "launch",
    "adapter": "CodeLLDB"
  }
]
```

### ビルドコマンドに基づいてデバッグターゲットを自動的に特定する

ビルドコマンドとして `cargo build` または `cargo test` を使用する場合、Zed は出力バイナリへのパスを推論できます。

```json [debug]
[
  {
    "label": "Build & Debug native binary",
    "adapter": "CodeLLDB",
    "build": {
      "command": "cargo",
      "args": ["build"]
    },
    // Rust を使用する場合、CodeLLDB（GDB ではない）では sourceLanguages が必須です
    "sourceLanguages": ["rust"]
  }
]
```
