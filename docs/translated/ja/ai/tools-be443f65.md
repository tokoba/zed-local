# ツール

Zed の組み込みエージェントは、コードベースの読み取り、検索、編集のためにこれらのツールを利用できます。これらのツールは、AI エージェントとの対話中に [Agent Panel](./agent-panel.md) で使用されます。

ツール操作に対する権限は、操作を自動的に許可するか、自動的に拒否するか、ケースバイケースで確認を求めるかなどを含めて設定できます。権限によって制御されるツールの一覧や詳細については、[Tool Permissions](./tool-permissions.md) を参照してください。

これらの組み込みツールに加えてカスタムツールを追加するには、[MCP servers](./mcp.md) を参照してください。

## 読み取り・検索ツール

### `diagnostics`

特定のファイルまたはプロジェクト全体についてエラーと警告を取得します。編集後に、さらに変更が必要かどうかを判断するのに役立ちます。
パスが指定されている場合、その特定のファイルに対するすべての診断結果を表示します。
パスが指定されていない場合、プロジェクト内のすべてのファイルについて、エラーと警告の件数を要約して表示します。

**例:** `src/parser.rs` を編集した後、そのパスを指定して `diagnostics` を呼び出すことで、すぐに型エラーを確認できます。多くのファイルにまたがる大規模なリファクタリングを行った後は、パスを指定せずに呼び出すことで、次にどこを修正するかを決める前に、プロジェクト全体のエラー件数を確認できます。

### `fetch`

URL を取得し、そのコンテンツを Markdown として返します。ドキュメントをコンテキストとして提供するのに便利です。

**例:** 連携コードを書く前に、最近のバージョンで破壊的な API 変更が導入されていないか確認するために、ライブラリの changelog ページを取得する。

### `find_path`

グロブパターン（「\**/*.js」のような）にマッチするファイルを素早く検索し、一致したファイルパスをアルファベット順で返します。

### `grep`

正規表現を使ってプロジェクト全体のファイル内容を検索します。ファイルパスを正確に知らなくてもコード内のシンボルを見つけるのに適しています。

**例:** 関数名を変更する前にすべての呼び出し箇所を見つけるには、`parse_config\(` を検索します。この正規表現は関数名の後に開きかっこが続くものにマッチするため、たまたま同じ文字列を含んでいるだけのコメントや変数名を除外できます。

### `list_directory`

指定したパス内のファイルとディレクトリを一覧表示し、ファイルシステムの内容の概要を提供します。

### `now`

現在の日付と時刻を返します。

### `open`

ユーザーのオペレーティングシステムで関連付けられているデフォルトアプリケーションを使って、ファイルまたは URL を開きます。

### `read_file`

プロジェクト内で指定されたファイルの内容を読み取り、そのファイル内容へアクセスできるようにします。

### `thinking`

エージェントがアクションを実行することなく、問題に取り組んだり、アイデアをブレインストーミングしたり、計画を立てたりできるようにします。複雑な問題解決に役立ちます。

### `web_search`

Web 上の情報を検索し、関連する Web ページからのスニペットとリンク付きで結果を提供します。リアルタイムな情報にアクセスするのに役立ちます。

**例:** 依存ライブラリの既知のバグが最近のリリースで修正されたかどうかを調べたり、ローカルのドキュメントが古い場合にサードパーティライブラリの現在の API シグネチャを確認したりする。

## 編集ツール

### `copy_path`

プロジェクト内のファイルまたはディレクトリを再帰的にコピーします。コンテンツを複製するときに、ファイルを手動で読み書きするよりも効率的です。

### `create_directory`

プロジェクト内の指定されたパスに新しいディレクトリを作成し、必要な親ディレクトリもすべて作成します（`mkdir -p` と同様）。

### `delete_path`

指定されたパスのファイルまたはディレクトリ（内容も再帰的に含む）を削除し、その削除を確認します。

### `edit_file`

特定のテキストを新しいコンテンツに置き換えることでファイルを編集します。

**例:** 関数シグネチャを更新する場合、エージェントは置き換えるべき正確な行を特定し、周辺のコードには手を触れずに更新版を提供します。広範囲な名前変更を行う場合は、最初に `grep` と組み合わせてすべての出現箇所を見つけます。

### `move_path`

プロジェクト内のファイルまたはディレクトリを移動またはリネームします。ファイル名のみが異なる場合はリネームを実行します。

### `restore_file_from_disk`

ディスクからファイル内容を再読み込みすることで、開いているバッファの未保存の変更を破棄します。編集をやり直す前にファイルをディスク上の状態にリセットするのに便利です。

### `save_file`

未保存の変更があるファイルを保存します。追加の編集を行う前にファイルを保存する必要がある場合に使用します。

### `terminal`

シェルコマンドを実行し、その出力をまとめて返します。呼び出しごとに新しいシェルプロセスを作成します。

**例:** Rust ファイルを編集した後に `cargo test --package my_crate 2>&1 | tail -30` を実行して、その変更によって既存のテストが壊れていないことを確認する。あるいは `git diff --stat` を実行して、タスクを完了する前にどのファイルが変更されたかを確認する。

## その他のツール

### `spawn_agent`

委任されたタスクを実行するために、独自のコンテキストウィンドウを持つサブエージェントを生成します。並行して調査を行ったり、自己完結したタスクを完了したり、結果だけが重要なリサーチを行ったりするのに便利です。各サブエージェントは、親エージェントと同じツールにアクセスできます。

**例:** 認証モジュールをリファクタリングしている間に、コードベースの他の箇所でセッショントークンがどのように検証されているかを調査するサブエージェントを生成する。親エージェントはその間も作業を続け、サブエージェントの調査が完了したらその結果をレビューすることで、両方のコンテキストウィンドウをそれぞれ 1 つのタスクに集中させておく。
