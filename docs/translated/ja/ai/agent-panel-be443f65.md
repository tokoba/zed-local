# Agent Panel

Agent Panel は、プロジェクト内のコードを読み取り、書き込み、実行できる AI エージェントと対話する場所です。
これは Zed の AI コード編集体験の中核であり、コード生成、リファクタリング、デバッグ、ドキュメント作成、一般的な質問などに使用できます。

[Command Palette](../getting-started.md#command-palette) から `agent: new thread` を実行するか、ステータスバーの ✨ アイコンをクリックして開きます。

## はじめに {#getting-started}

初めて Agent Panel を使用する場合は、少なくとも 1 つの LLM プロバイダまたは外部エージェントを設定しておく必要があります。
そのための方法は次のとおりです。

1. [Pro プランを購読](https://zed.dev/pricing)して、ホストされたモデルにアクセスできるようにする
2. Anthropic のようなモデルプロバイダや OpenRouter のようなモデルゲートウェイなどからの [自分の API キーを使用する](./llm-providers.md#use-your-own-keys)
3. [Gemini CLI](./external-agents.md#gemini-cli) や [Claude Agent](./external-agents.md#claude-agent) のような [外部エージェント](./external-agents.md) を使用する

## 概要 {#overview}

LLM プロバイダまたは外部エージェントを設定したら、メッセージエディタに入力し、`enter` を押して送信します。
スペースが必要な場合は {#kb agent::ExpandMessageEditor} でエディタを拡張できます。

レスポンスはストリーミング表示され、モデルがどの [ツール](./tools.md) を使用しているかを示すインジケータが表示されます。
ここから何ができるかについては、以下のセクションで説明します。

> [Gemini CLI](./external-agents.md#gemini-cli) や [Claude Agent](./external-agents.md#claude-agent) のような外部エージェントでは、以下で説明する機能の一部がサポートされて *いない* 場合があります。たとえば、*履歴からスレッドを復元する*、*チェックポイント*、*トークン使用量の表示* などです。
> これらの機能の有無はエージェントによって異なります。

### 新しいスレッドの作成 {#new-thread}

デフォルトでは、Agent Panel は Zed のファーストパーティエージェントを使用します。

別のエージェントを選択するには、Agent Panel 右上のプラスボタンから、最初からインストールされている [外部エージェント](./external-agents.md) のいずれかを選びます。

### メッセージの編集 {#editing-messages}

モデルに送信した任意のメッセージは編集可能です。
メッセージを含むカードをクリックし、プロンプトや新しいコンテキストを調整して再送信できます。

### メッセージのキューイング

エージェントが生成中の状態で送信されたメッセージは、デフォルトではキューに入れられます。

Zed エージェントの場合、キューに入ったメッセージは次のターン境界、通常はツール呼び出しとレスポンスの間で送信されます。一方、外部エージェントの場合、メッセージは生成の終了時に送信されます。

キューに入っているメッセージは、個別またはすべてまとめて編集または削除できます。
また、停止ボタンをクリックするか、キューに入っているメッセージの「Send Now」（ダブル enter）をクリックすることで、いつでも即座にエージェントを中断できます。

### チェックポイント {#checkpoints}

モデルが編集を行うたびに、メッセージの一番上に「Restore Checkpoint」ボタンが表示され、メッセージの前の状態にコードベースを戻せるようになります。

スレッドを編集の途中で中断した場合でも、チェックポイントボタンは表示されます。これは、多くの場合、エージェントが望む方向に進んでいないと気付き、元に戻したくなるタイミングだからです。

### コンテキストメニュー {#context-menu}

スレッドビュー内の任意のエージェントのレスポンスを右クリックすると、次のアクションを含むコンテキストメニューにアクセスできます。

- **Copy Selection**: 現在選択されているテキストを Markdown としてコピーします（テキストが選択されている場合に利用可能）。
- **Copy This Agent Response**: 右クリックしたエージェントのレスポンス全体のテキストをコピーします。
- **Scroll to Top / Scroll to Bottom**: 現在位置に応じて、スレッドの先頭または末尾までスクロールします。
- **Open Thread as Markdown**: スレッド全体を Markdown ファイルとして新しいタブで開きます。

### スレッドのナビゲーション {#navigating-the-thread}

会話が長くなってきた場合は、パネル下部のスクロール矢印ボタンを使って、直近のプロンプトやスレッドの先頭にジャンプできます。スレッドペインにフォーカスがあるときは、矢印キー、Page Up/Down、Home/End、Shift+Page Up/Down を使ってスレッドをスクロールしたり、メッセージ間を移動したりすることもできます。

フォーカスがメッセージエディタにあるときは、スレッドをナビゲートするために {#kb agent::ScrollOutputPageUp}、{#kb agent::ScrollOutputPageDown}、{#kb agent::ScrollOutputToTop}、{#kb agent::ScrollOutputToBottom}、{#kb agent::ScrollOutputLineUp}、{#kb agent::ScrollOutputLineDown} を使用できます。また、{#kb agent::ScrollOutputToPreviousMessage} と {#kb agent::ScrollOutputToNextMessage} を使って、自分のプロンプト間をジャンプできます。

### 履歴のナビゲーション {#navigating-history}

最近更新されたスレッドを素早く移動するには、パネルのエディタにフォーカスがある状態で {#kb agent::ToggleNavigationMenu} のキー割り当てを使うか、パネル右上のメニューアイコンボタンをクリックします。
これにより、最近更新されたスレッド上位 6 件を表示するドロップダウンが開きます。

すべての過去の会話を表示するには、同じメニュー内の `View All` オプションを選択するか、{#kb agent::OpenHistory} のキー割り当てを使用します。

スレッドのタイトルは、会話の内容に基づいて自動生成されます。
ただし、タイトルをクリックして入力することで手動で編集したり、パネル右上の三点メニュー内の「Regenerate Thread Title」ボタンをクリックして再生成したりすることもできます。

### エージェントに追従する {#following-the-agent}

パネル左下の十字線アイコンをクリックすると、エージェントがファイルを読み書きするのに合わせて追従できます。
エージェントが操作した各ファイルに、エディタが自動的にジャンプします。

また、メッセージ送信時に `cmd`/`ctrl` を押しながら送信すると、自動で追従することもできます。

### 通知を受け取る {#get-notified}

Agent にプロンプトを送信したあとで Zed をバックグラウンドに回した場合、生成が完了したタイミングで次の方法で通知を受け取るかどうかを選択できます。

- 画面右上に表示される視覚的な通知
- サウンド通知

これらの通知は併用することも、どちらか一方だけを使用することもできます。また、`agent.notify_when_agent_waiting` と `agent.play_sound_when_agent_done` 設定キーを使って、両方を完全にオフにすることも含めてカスタマイズできます。

### 変更のレビュー {#reviewing-changes}

エージェントがプロジェクトに変更を加えると、どのファイルが何件、何行編集されたかがパネルに表示されます。

どのファイルが編集されたかを具体的に確認するには、メッセージエディタ直上に表示されるアコーディオンバーを展開するか、`Review Changes` ボタン（{#kb agent::OpenAgentDiff}）をクリックします。これにより、すべての変更を含む特別なマルチバッファタブが開きます。

個々の変更ハンクごと、またはエージェントが行った変更の全体をまとめて、受け入れたり却下したりできます。

編集された差分はシングルトンバッファにも表示されます。
アクティブなタブに AI による編集がある場合、マルチバッファと同じ受け入れ/却下コントロール付きの差分が表示されます。
これを無効にしたい場合は、`agent.single_file_review` 設定を使ってオフにできます。

## コンテキストの追加 {#adding-context}

エージェントはコードベースを検索して関連するコンテキストを見つけられますが、明示的にコンテキストを提供すると、レスポンスの品質が向上し、レイテンシが短くなります。

メッセージエディタで `@` を入力してコンテキストを追加します。
ファイル、ディレクトリ、シンボル、過去のスレッド、ルールファイル、診断情報をメンションできます。
バッファからコピーした複数行のコードの選択範囲を貼り付けると、Zed はそれらをファイルコンテキスト付きの @ メンションとして自動的に整形します。
この自動フォーマットを行わずにコンテンツを貼り付けるには、{#kb agent::PasteRaw} を使用してテキストを生のまま直接貼り付けてください。

### コンテキストとしての選択範囲

さらに、バッファまたはターミナル内のテキストを選択し、{#kb agent::AddSelectionToThread} キーバインドを使用するか、{#action agent::AddSelectionToThread} アクションを実行するか、メッセージエディタの `+` メニューで "Selection" 項目を選択することで、その選択範囲をコンテキストとして追加することもできます。

### コンテキストとしての画像

ビジョンモデルをサポートしているプロバイダーに対しては、プロンプトに画像を添付することも可能です。
OpenAI GPT-4o 以降、Anthropic Claude 3 以降、Google Gemini 1.5 および 2.0、さらに Bedrock のビジョンモデル（Claude 3+、Amazon Nova Pro / Lite、Meta Llama 3.2 Vision、Mistral Pixtral）は、いずれも画像入力をサポートしています。

画像を追加するには、@ メンションを使ってプロジェクトディレクトリ内を検索するか、ファイルシステムから Agent パネルのメッセージエディタに直接ドラッグします。
画像をコピーして貼り付けることもできます。

## トークン使用量 {#token-usage}

Zed は、パネルのメッセージエディタ内のプロファイルセレクタ付近に、現在アクティブなスレッドで消費しているトークン数を表示します。

モデルのコンテキストウィンドウの上限に近づくと、現在のスレッドを要約してコンテキストとして追加した新しいスレッドを開始することを提案するバナーが、メッセージエディタの上部に表示されます。
同じことは、進行中のスレッドに対していつでも右上の "Agent Options" メニューから行うこともでき、その中にある "New from Summary" ボタンを使うか、新しいスレッド内で過去のスレッドを単に @ メンションすることで実行できます。

## モデルの切り替え {#changing-models}

LLM プロバイダーを [カスタム API キー](./llm-providers.md) または [Zed のホスト型モデル](./models.md) で設定すると、メッセージエディタ上のモデルセレクタをクリックするか、{#kb agent::ToggleModelSelector} キーバインドを使うことで、それらのモデルを切り替えられます。

> 同じモデルが複数のプロバイダーから提供される場合があります。たとえば、Claude Sonnet 4.5 は Zed Pro、OpenRouter、Anthropic などさまざまな経路で利用できます。
> 使用したいモデルについて、モデルセレクタ内でモデルの左側に表示されるロゴによって区別される、正しいモデルの ***プロバイダー*** を選択していることを確認してください。

### モデルのお気に入り登録

特定のモデルをお気に入りとしてマークするには、モデルセレクタでモデルにカーソルを合わせたときに表示される星形アイコンボタンをクリックするか、設定ファイルの `agent.favorite_models` 設定キーを通じて行えます。

モデルセレクタを開かずに、お気に入りのモデルを {#kb agent::CycleFavoriteModels} で順番に切り替えることもできます。

## ツールの使用 {#using-tools}

Agent パネルはツールコーリングをサポートしており、エージェント主導の編集を可能にします。
Zed には、コードベースの検索、ファイル編集、ターミナルコマンドの実行などのための、いくつかの [組み込みツール](./tools.md) が含まれています。

[MCP Servers](./mcp.md) を通じて、利用可能なツール群を拡張することもできます。

### プロファイル {#profiles}

プロファイルは、ツールをグループ化するための仕組みとして機能します。
Zed には 3 つの組み込みプロファイルが用意されており、必要に応じて任意の数のカスタムプロファイルを作成できます。

#### 組み込みプロファイル {#built-in-profiles}

- `Write`: LLM がファイルに書き込んだりターミナルコマンドを実行したりできるツールを備えたプロファイルです。
  これは基本的に、すべての組み込みツールが有効になっているプロファイルです。
- `Ask`: 読み取り専用ツールを備えたプロファイルです。
  エージェントが変更を加える心配をせずに、コードベースに関する質問を行うのに最適です。
- `Minimal`: ツールを一切含まないプロファイルです。
  コードベースの知識が不要な、LLM との一般的な会話に最適です。

各プロファイルで有効になっている具体的なツールは、プロファイルセレクタボタン > `Configure` ボタン > 確認したいプロファイルの順にクリックして確認できます。

または、コマンドパレットで {#action agent::ManageProfiles} を実行するか、{#kb agent::ManageProfiles} キーバインドを直接使用して、プロファイル管理モーダルにアクセスすることもできます。

モーダルを開かずに利用可能なプロファイルを切り替えるには、{#kb agent::CycleModeSelector} を使用します。

#### カスタムプロファイル {#custom-profiles}

Agent Profile モーダルからカスタムプロファイルを作成することもできます。
そこから `Add New Profile` を選択するか、既存のプロファイルをフォークしてカスタム名と好みのツールセットを設定できます。

組み込みプロファイルを上書きすることも可能です。
Agent Profile モーダルで組み込みプロファイルを選択し、`Configure Tools` に移動して、残したいツールや削除したいツールを並べ替えます。

Zed は、このプロファイルを、上書きしたデフォルトプロファイルと同じプロファイル名で設定内に保存します。

すべてのカスタムプロファイルは、UI から、または設定ファイル内の `agent.profiles` キーの下を手作業で編集できます。

カスタムプロファイルを削除するには、Agent Profile モーダルを開き、削除したいプロファイルを選択して、削除ボタンをクリックします。

### ツールの権限

> **注記:** Zed v0.224.0 以降では、ツールの承認は `agent.tool_permissions.default` で制御されます。
> それ以前のバージョンでは、`agent.always_allow_tool_actions` ブール値（デフォルト `false`）で制御されていました。

Zed の Agent パネルでは、ツールの承認動作を制御するために `agent.tool_permissions.default` 設定が提供されています:

- `"confirm"` (デフォルト) — いかなるツールアクションを実行する前にも承認を求めます
- `"allow"` — 確認を求めずにツールアクションを自動承認します
- `"deny"` — すべてのツールアクションをブロックします

エージェントがあるアクションの許可を要求したとき、確認メニューには 1 回だけ許可または拒否するオプションに加えて、ツールレベルのデフォルトを設定する "Always for <tool>" の選択肢が含まれます。
Zed が入力から安全なパターンを抽出できる場合には、`always_allow` / `always_deny` ルールを追加する、パターンベースの "Always for ..." の選択肢も提示されます。
MCP ツールでは、ツールレベルのデフォルトのみがサポートされます。

`"default": "allow"` に設定していても、ツールごとの `always_deny` および `always_confirm` パターンは引き続き尊重されます。そのため、特定のアクションをブロックしたり確認を挟んだりしつつ、ほとんどのアクションを自動承認することができます。

ツール権限の仕組みや、さらにカスタマイズする方法などの詳細については、[ツール権限の仕組み](./tool-permissions.md) を参照してください。

### モデルのサポート {#model-support}

ツールコーリングは、各モデルおよびモデルプロバイダーごとに個別にサポートされている必要があります。
そのため、組み込みツールが存在していても、それらを利用できないモデルもあります。
このケースに該当するモデルを選択すると、"No tools" というラベルが表示されるはずです。

[Zed のホスト型モデル](./models.md) はすべて、標準でツールコーリングをサポートしています。

### MCP Servers {#mcp-servers}

組み込みツールと同様に、特定の MCP Server に含まれるすべてのツールをサポートしていないモデルもあります。
Zed の UI は、モデルセレクタ付近に表示される警告アイコンを通じてそのことを知らせます。

## エラーとデバッグ {#errors-and-debugging}

エラーや LLM の異常な動作に遭遇した場合は、`agent: open thread as markdown` を使ってスレッドを Markdown として開き、それを GitHub issue に添付してください。

パネルのエディタにフォーカスがある状態で、サムズダウンボタンの右側にあるファイルアイコンボタンをクリックすることでも、スレッドを Markdown として開くことができます。

## フィードバック {#feedback}

Zed のシステムプロンプトやツールの改善に役立てるために、エージェントの応答を評価できます。
> 応答を評価すると、その応答に関連するあなたのデータが Zed のサーバーに送信されることに注意してください。
> Zed による AI 改善、プライバシー、セキュリティへの取り組みの詳細については、[AI Improvement](./ai-improvement.md) および [Privacy and Security](./privacy-and-security.md) を参照してください。
> ***Zed のサーバーにデータを永続的に保存されたくない場合は、評価しないでください***。
> あなたが明示的に応答を評価しない限り、当社の Agentic オファリングを改善する目的でデータを収集することはありません。

Zed のシステムプロンプトとツールの改善に役立てるため、各応答の末尾にあるサムズアップ / サムズダウンのコントロールで応答を評価してください。
サムズダウンを選択した場合は、新しいテキストエリアが表示され、何が起きたのかをより具体的に記述できます。

エージェントが応答した後であればいつでも、そのスレッドに対してフィードバックを送ることができ、同じスレッド内で複数回フィードバックすることもできます。
